4. ПОДРОБНЫЙ АУДИТ ПО РАЗДЕЛАМ
4.1 DESIGN / ART DIRECTION
Цветовая палитраработает отлично. Cyan (71e7ff) как primary, violet, rose, gold, green это palette для «тёмной магии» и «светлого дня» одновременно. Переключение tema переключает весь мир это очень сильное дизайнрешение.
Типографика самое слабое место в дизайне. Inter через systemui это нейтральный выбор, который работает, но не создаёт характер. Для игровой студии, которая продаёт «магию», нужен хотя бы один акцентный шрифт для заголовков. Рекомендую рассмотреть variable font уровня Satoshi, Cabinet Grotesk или Clash Display они грузятся быстро и дают personality без лицензионных проблем.
Hero Section сильный. Живая Nature Seed preview с анимацией sketch→guide water→bloom создаёт правильный контекст за 3 секунды. Но: на мобайле herogrid схлопывается в колонку, и Nature preview уходит вниз пользователь видит только текст, не видит игру.
Карточки игр лучшее на сайте. Каждая карта имеет свою CSSанимацию, свой характер, свою атмосферу. Ball is God с плавающими облаками и качающейся башней это серьёзный уровень CSS art.
Слабые места:
Section "Studio Notes" с тремя цитатами слишком тонкий раздел, выглядит как padding
Footer без реальных ссылок разрушает доверие
Brand mark в хедере логотип слишком мелкий (42×42px), теряется при первом взгляде
Нет визуального разделителя между секциями сайт читается как один длинный поток

4.3 FRONTEND / CODE QUALITY
HTML хорошо, с оговорками:
Семантика правильная: header, main, footer, section, article, nav. Ariaатрибуты корректны. Но:
Нет <meta property="og:image"> / og:title / og:description ссылка в Telegram/Twitter выглядит как пустота
Нет <link rel="icon"> браузер делает запрос на /favicon.ico который даёт 404
Нет <link rel="canonical">
В <head> нет <link rel="preload"> для главного webpлоготипа
CSP в <meta> не включает frameancestors и upgradeinsecurerequests это корректно (они работают только как HTTPзаголовки), но стоит добавить комментарий
CSS функциональный, но монолитный:
~2500 строк в одном файле это предел читаемости. Нет ни одного компонента, вынесенного отдельно. Перед масштабированием нужно разбить на слои:
tokens.css CSS variables
base.css reset, typography, layout
components/ header, cards, modals, forms
animations.css keyframes
Дублирование кода:.paintcovericon, .ballcovericon, .candycovericon, .naturecovericon у всех идентичные стили (position, zindex, aspectratio, border, borderradius, objectfit, boxshadow, transition). Это можно унифицировать в один класс .gamecovericon с модификаторами.
JavaScript серьёзная проблема с мёртвым кодом:
В функции drawCat(now) есть блок:
javascript
if (mascotImage.complete && mascotImage.naturalWidth) {
 // ... рисует изображение ...
 ctx.restore();
 return;  // ← РАННИЙ RETURN
}
// ... 200+ строк кода рисования векторного кота
// Этот код НИКОГДА не выполняется если mascotImage загружен
После return идёт ещё один ctx.save() / ctx.restore() блок и потом ещё один полный блок рисования. Это ~300 строк неиспользуемого кода. Если mascotImage не загружен, функция возвращается пустым (нет else). Нужно:
javascript
function drawCat(now) {
 if (!mascotImage.complete  !mascotImage.naturalWidth) {
 drawFallbackCat(now); // вынести в отдельную функцию
 return;
 }
 drawImageCat(now); // основной путь
}
Другие JSпроблемы:
getEventPoint возвращает source.clientX/Y из click event но event.touches[0] на clickсобытии это undefined, поэтому используется сам event. Работает, но нечитаемо.
state.clickBursts и state.trails фильтруются каждый кадр это создаёт мусор для GC. Лучше использовать объектный пул.
window.clearTimeout(showToast.timer) хранить timerID как свойство функции это антипаттерн. Использовать переменную в closure.
4.4 PERFORMANCE
Главный риск: пять слоёв тяжёлых эффектов одновременно
На страницу загружается:
1. Canvas animation (requestAnimationFrame, 60fps) drawBackground рисует 45 градиентных слоёв каждый кадр
2. CSS backdropfilter: blur() на хедере, всех модалках, magichud, naturepreviewtitle, naturecycle
3. CSS animations на всех 4 игровых картах (ballcloudfield: 16 анимирующихся облаков, candybg: 10 слоёв, nature: 8 анимаций, paint: 6)
4. CSS filter: dropshadow() на множестве элементов
5. IntersectionObserver reveals
На среднем Android телефоне ($200–400 уровня) это может давать 20–30 FPS при скролле.
Что конкретно делать:
backdropfilter: blur() заменить на background: var(surfacestrong) с повышенной непрозрачностью там, где размытие не критично. Оставить только на header и contactModal.
CSS анимации на картах использовать willchange: transform только на активно анимирующихся элементах, и убирать его после окончания анимации через JS.
drawBackground бэкграунд не меняется между кадрами (только now для покачивания). Рисовать его в отдельный offscreen canvas и копировать это сократит время перерисовки с ~8ms до ~1ms.
javascript
const bgCanvas = new OffscreenCanvas(width, height);
const bgCtx = bgCanvas.getContext('2d');
// рисуем фон раз в секунду или при смене темы
// основной ctx.drawImage(bgCanvas, 0, 0) каждый кадр
LCP (Largest Contentful Paint):Вероятно, это <h1> или логотип. Добавить:
html
<link rel="preload" href="assets/willowinworldlogoday.webp" as="image">
CLS (Cumulative Layout Shift):containintrinsicsize: auto 980px на секциях снижает CLS, но природа canvasfax/heropanel с minheight может вызывать небольшой сдвиг. Использовать aspectratio вместо minheight где возможно.
Шрифты:System font stack не создаёт FOUT это плюс для производительности.

4.7 SECURITY ДЕТАЛЬНЫЙ АУДИТ
Оценка: 9/10. Это один из самых хорошо защищённых статических сайтов.
CSPанализ:
defaultsrc 'self'
scriptsrc 'self'        ← только локальные скрипты
stylesrc 'self'         ← только локальные стили
connectsrc 'none'       ← полный блок сети из JS
formaction 'none'       ← форма не может отправить данные
frameancestors 'none'   ← антикликджекинг
Это образцово для статики. Но:
Проблема 1: trustedtypes 'none' + requiretrustedtypesfor 'script'
Эта комбинация означает: любая попытка присвоить строку опасному DOMсинку (innerHTML, script.src и т.д.) будет заблокирована, и никаких Trusted Type policies создать нельзя. Код корректно использует только безопасные DOMAPI (textContent, createElement, style.setProperty, replaceChildren). Это работает сейчас. Но если в будущем добавить любую библиотеку (даже Google Analytics) она сломается. Нужно это задокументировать.
Проблема 2: HSTS без includeSubDomains и preload
StrictTransportSecurity: maxage=31536000
Рекомендуется:
StrictTransportSecurity: maxage=63072000; includeSubDomains; preload
Проблема 3: securitycheck.mjs в публичной папке
Этот файл читает другие файлы через fs/promises и содержит паттерны всех securityпроверок. При деплое на Netlify/Vercel он будет доступен публично. Переместить в .scripts/ или добавить в .gitignore для публичного репо.
Проблема 4: Контактная форма без backend = нет spamзащиты
Сейчас форма не отправляет данные. Когда будете подключать: используйте Netlify Forms или Formspree с reCAPTCHA v3 или Turnstile (Cloudflare). Без этого 100% спам.
XSSриски:Практически нулевые. Нет innerHTML, нет eval, нет внешних скриптов. textContent везде. Отлично.
localStorage:Используется только для темы. Не является риском.
Что нет и должно быть:
CacheControl: public, maxage=31536000, immutable  ← для static assets
CacheControl: nocache                              ← для index.html
4.8 MOBILE AUDIT
Hero на телефоне:При 920px herogrid переключается в single column. Nature Seed preview уходит вниз за fold первый экран показывает только текст. Это большая потеря wowэффекта. Решение: на мобайле показать компактную heropreview выше текста (поменять порядок flexэлементов через order).
Кнопки:minheight 44px правильно. На 640px grid переключается в gridtemplatecolumns: 1fr хорошо.
Текст:clamp(3.2rem, 8.2vw, 7.6rem) для h1 на телефоне ~280px шириной даст ~22.9px. Это нормально, но маловато для такого большого h1. Пересчитать: clamp(2.6rem, 11vw, 7.6rem).
Backdropfilter на mobile Safari (iOS):backdropfilter: blur(18px) на хедере вместе с анимированным canvas под ним это stack overflow для GPU на iPhone 11 и старше. Конкретное решение:
css
@supports not (backdropfilter: blur(1px)) {
 .siteheader {
 background: var(surfacestrong);
 }
}
Touch события:handlePointerDown вешается на window.addEventListener("click") и window.addEventListener("touchend"). На iOS это означает двойной триггер. Нужно:
javascript
window.addEventListener("touchend", handlePointerDown, { passive: true });
// И убрать click если touch был
Canvas на мобайле:state.particleCount = 34 на smallScreen правильно. Но drawCastle, drawBackground, drawWillowFrame всё ещё рисуются в полном объёме. На мобайле можно упростить drawBackground убрать drawWillowFrame и drawCastle, оставить только небо, облака и холмы.

7. ЗАЩИТА АССЕТОВ ЧТО РЕАЛЬНО РАБОТАЕТ
Реально полезно:
Водяные знаки на промоарте (полупрозрачный логотип в углу) усложняет прямое использование
Выкладывать только weboptimized webp с уменьшенным разрешением (1440px максимум), исходники 4K хранить offline
robots.txt: Disallow: /assets/ блокирует индексацию ботами, не мешает браузеру
Hotlink protection через CDN (Cloudflare) запрещает использование ваших изображений на чужих сайтах
Copyright блок в футере + DMCAконтакт: copyright@willowinworld.com
ContentDisposition: inline headers предотвращают автоматическое скачивание

Проблема 1: css() вызывается каждый кадр
javascript
function drawStars(now) {
 const cyan = css("cyan");      // getComputedStyle каждый кадр
 const violet = css("violet");  // getComputedStyle каждый кадр

Проблема 2: Object allocation в render loop

function getEventPoint(event) {
 const source = event.touches?.[0] ?? event.changedTouches?.[0] ?? event;
 return { x: source.clientX, y: source.clientY }; // ← новый объект каждый раз
}
При touchmove это создаёт новый объект 60 раз в секунду. GCдавление. Решение:
javascript
const _eventPoint = { x: 0, y: 0 }; // Переиспользуемый объект
function getEventPoint(event) {
 const source = event.touches?.[0] ?? event.changedTouches?.[0] ?? event;
 _eventPoint.x = source.clientX;
 _eventPoint.y = source.clientY;
 return _eventPoint;
}
Проблема 3: state.trails.push() без ограничения длины в одном месте
javascript
// handlePointerMove:
state.trails.push({ x: point.x, y: point.y, t: state.pointer.lastMove });
if (state.trails.length > 48) state.trails.shift(); // ← shift() на массиве = O(n)
Array.shift() на каждом кадре при быстром движении мыши это O(n) операция. Лучше использовать circular buffer:
javascript
class CircularBuffer {
 constructor(size) {
 this.buf = new Array(size);
 this.head = 0;
 this.size = 0;
 this.capacity = size;
 }
 push(item) {
 this.buf[this.head] = item;
 this.head = (this.head + 1) % this.capacity;
 if (this.size < this.capacity) this.size++;
 }
 toArray() {
 if (this.size < this.capacity) return this.buf.slice(0, this.size);
 return [...this.buf.slice(this.head), ...this.buf.slice(0, this.head)];
 }
}
const trails = new CircularBuffer(48);
Проблема 4: drawBackground рисует сложные объекты каждый кадр

4 треугольника крыш

1 базу замка
Всего ~20+ canvas draw calls, каждый кадр, 60fps = 1200 canvas calls/сек только для замка, который практически не меняется (меняется только global.Alpha на 2 значения).

// В drawBackground:

 transform: scale(1.04);

}

3. Анимируется .painthero (transform)
4. Появляется .painthovericon (opacity + transform)
5. Изменяется bordercolor карты
5 compositing layers одновременно. На mobile GPU риск dropped frames.

Статус: ЗАЩИЩЕНО

Статус: ЗАЩИЩЕНО

Статус: НЕ ПРИМЕНИМО

Код читает это значение: const theme = localStorage.getItem("willowtheme"); return theme === "dark"  theme === "light" ? theme : null;
Валидация присутствует. Атакующий не может засунуть скрипт через localStorage

Проблема: Touch events на canvas
javascript
window.addEventListener("touchend", handlePointerDown, { passive: true });
passive: true на touchend означает вы не можете вызвать preventDefault(). Это нормально для canvasкликов, но если пользователь тапает на секретный glint, который является <button> может быть конфликт с click event.
Текущий код в handlePointerDown:
javascript
const target = event.target;
if (target instanceof Element && target.closest("button, a, input, textarea, select, .modaldialog")) return;
Этот guard правильный он игнорирует клики по кнопкам. Но touchend на window + click на window это двойной триггер на iOS (iOS генерирует synthetic click ~300ms после touchend). Решение через touch detection:
javascript
let touchStarted = false;
window.addEventListener('touchstart', () => { touchStarted = true; }, { passive: true });
window.addEventListener('touchend', handlePointerDown, { passive: true });
window.addEventListener('click', (event) => {
 if (touchStarted) {
 touchStarted = false;
 return; // уже обработано в touchend
 }
 handlePointerDown(event);
});

1. ЧТО ЕЩЁ УДАЛОСЬ НАЙТИ
По дизайну
blockquote в Studio Notes не имеет <cite> семантически неверно и выглядит как цитата без источника
Прогрессбары для игр не имеют визуальной анимации при появлении упущен emotional moment
Цвет grass: 0b6056 объявлен в dark theme, но grass: 49b68a в light theme используется только в body::after один раз. Токен используется неэффективно
Секция "Systems" и секция "Principles" визуально почти идентичны (тот же grid, та же карточка, те же иконки) пользователь не понимает разницу между ними

Фильтры игр не запоминают состояние при скролле вниз и обратно пользователь вернулся, фильтр сбросился
Нет состояния "empty state" при фильтрации если фильтр не даёт результатов, просто пропадают карточки без объяснения
Кнопка "Follow Development" ведёт в контактную форму это не то, что ожидает пользователь, который нажимает "Follow"
Модальное окно игры (gameModal) не имеет URL нельзя поделиться ссылкой на конкретную игру
При открытии gameModal scroll position страницы сохраняется, но при закрытии нет плавного возврата фокуса к нужной карточке (код есть, но activeGameTrigger.focus() без scroll в viewport)
В FAQ нет поиска при масштабировании FAQ до 15+ вопросов это станет проблемой
По frontend
drawGrass() функция объявлена в scripts.js но нигде не вызываетсяв render loop это ещё один блок мёртвого кода помимо drawCat
state.connected при reset в startPlayMode() очищается через state.connected = [], но state.nextStar = 0 при этом старые burstэффекты от предыдущей игры могут всё ещё анимироваться если state.clickBursts не очищается

В initSmoothAnchors() closeMenu() вызывается до target.scrollIntoView() на мобайле закрытие меню вызывает layout recalculation, который может прервать smooth scroll
const mascotImage = new Image() создаётся до resize() и до startLoop(), но mascotImage.src устанавливается сразу если скрипт выполняется быстро, load event может сработать до регистрации listener

drawStorybookArches() использует ctx.bezierCurveTo с 3 paths каждый кадр это не кешируется
canvas.getContext("2d", { alpha: true }) alpha: true означает браузер должен каждый кадр делать alpha compositing поверх страницы. Для canvasфона правильнее { alpha: false } и самостоятельно рисовать background

window.addEventListener("resize", resize, { passive: true }) при resize пересоздаются всечастицы через seedScene(). Если пользователь активно ресайзит окно (например, splitscreen на iPad) это постоянная пересборка массивов

5. ПРАКТИЧЕСКИЙ ПЛАН
🔴 Сделать в первую очередь
Race condition с mascotImage
Переставить mascotImage.src после регистрации addEventListener("load", ...). В текущем коде const mascotImage = new Image(); mascotImage.src = "..." выполняется до listener если браузер имеет изображение в memory cache, load fire происходит синхронно и startLoop() никогда не вызывается. Это объясняет редкие репорты "canvas не запускается при повторном посещении страницы".
FAQ accordion fallback для Safari < 16
Добавить maxheight: 0; overflow: hidden как базовые стили с maxheight: 2000px для открытого состояния как fallback перед gridtemplaterows. Это затрагивает потенциально 812% мобильных пользователей на старых iPhone.
Landscape mobile hero section
Секция minheight: 100svh на landscape iPhone 14 = примерно 390px. С paddingtop: calc(76px + 70px) = 146px остаётся только ~244px для всего контента. Добавить специальный breakpoint:
css
@media (orientation: landscape) and (maxheight: 500px) {
 .section:firstoftype { paddingtop: calc(var(headerh) + 20px); }
 .hero { minheight: auto; }
}
Ariapressed на filter buttons
Критично для accessibility compliance. Без этого фильтры недоступны для screen readers.
arialabel на game card articles
Добавить arialabel="Nature Seed DrawtoSolve Physics Puzzle" к каждой карточке.
Empty state для game filters
Добавить hidden .gamesempty элемент: "No games match this filter" с visibility toggle в initFilters().
🟠 Проверить после этого
Контрастность muted цветов
Проверить контраст:
Dark theme: muted: c2d9e2 на bg: 031735 → нужно проверить через WebAIM Contrast Checker
Light theme: muted: 456b78 на bg: fcfff2 → аналогично
muted2 везде где используется для body text
Если контраст ниже 4.5:1 для текста 16px и меньше это WCAG AA нарушение.
canvas getContext alpha: false
Переключить и протестировать визуально во всех браузерах. Потенциальный прирост производительности при минимальном риске.
initReveals() visual pop
Элементы получают opacity: 0 через JS после того как они уже отрендерились. На медленных CPU это создаёт FOUCподобный эффект. Решение: добавить [datareveal] { opacity: 0; transform: translate3d(0, 28px, 0) scale(0.985); } прямо в CSS, убрать JSустановку атрибута как trigger для opacity.
drawGrass() решить: удалить или подключить
Функция полностью реализована (grass blade rendering, ground gradient), но не вызывается. Либо добавить в render loop между drawPaintedValley и drawWillowFrame, либо удалить. Это дизайнрешение, но неопределённость в коде технический долг.
Resize throttle на iPad
Обернуть resize handler в RAFdebounce. На iPad Pro с splitscreen resize events могут приходить быстрее чем 60fps.
scrollIntoView + closeMenu порядок
Поменять порядок: сначала target.scrollIntoView, потом closeMenu(). Или использовать setTimeout(() => closeMenu(), 400) после начала scroll.
naturecycle hardcoded top: 198px
Заменить на относительное позиционирование: top: calc(var(naturetitleheight, 190px) + 8px) или переработать layout через flexbox внутри превью.
Structured data JSONLD
Добавить минимальный Organization schema и SoftwareApplication для каждой игры. Занимает 30 минут, влияет на Google rich results.
securitycheck.mjs переместить
Если деплой через CI/CD этот файл должен быть в /scripts/ или в .github/workflows/, не в корне рядом с index.html.

7. ЧЕСТНЫЙ ВЫВОД
Самый надёжный фикс:mascotImage.src после listener это единственный настоящий баг, который может полностью сломать главный интерактивный элемент (canvas с котом) при повторном посещении с прогретым кешем. Ноль риска, максимальный эффект.
Второй по важности:FAQ fallback для Safari < 16. Это затрагивает реальных пользователей прямо сейчас каждый на iPhone с iOS 15 видит нерабочий FAQ. Это не гипотетический риск.
Не использовать:JS obfuscation для "защиты ассетов" это ухудшает производительность, усложняет дебаггинг, не защищает изображения, и может сломать strict CSP изза evalпаттернов которые используют некоторые obfuscators. Единственный реальный результат замедленный сайт.
Что нужно проверить перед финальным решением:Контрастность muted цветов это единственное место где может быть WCAG AA нарушение, которое не очевидно по коду без инструмента. Нужен реальный замер.
Неопределённость:Поведение gridtemplaterows animation в Samsung Internet последних версий (Chromiumbased) технически должно работать, но Samsung модифицирует Chromium. Нужно тестирование.
Что может стать проблемой при росте:Весь JavaScript один монолитный IIFE в одном файле. При добавлении Devlog, Press Kit, отдельных страниц игр этот паттерн не масштабируется. Уже сейчас скрипт ~600 строк. При 1500+ строках поддержка становится проблемой. Момент перехода на модульную архитектуру (ES modules + esbuild) это следующий технический шаг перед масштабированием.
Что обязательно до публикации:Рабочая форма, реальные соцсети в футере, favicon, OGтеги, mascotImage.src race condition fix, FAQ Safari fallback, landscape mobile fix, ariapressed на фильтрах.
Что можно оставить на потом:Structured data, magic cursor, Konami code, canvas alpha: false оптимизация, модульная архитектура JS.
Подтверждённые советы:canvas alpha: false performance gain подтверждён в Chrome developer documentation и множестве performance audits (Paul Lewis, Jake Archibald); gridtemplaterows Safari < 16 issue подтверждён в caniuse.com и многочисленных GitHub issues; mascotImage race condition стандартный паттерн описан в MDN HTMLImageElement docs.
Где нужны дополнительные тесты:Точный FPS impact от 16 CSSанимаций облаков на конкретных моделях Android зависит от GPU и версии драйвера, невозможно предсказать без реального тестирования на целевых устройствах.
