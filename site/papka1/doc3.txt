2. Главные проблемы (критические)
CSS монолит.styles.css — почти 9 000 строк плоского кода без разделения на модули, без CSS custom properties по компонентам, без слоёв @layer. Это уже сейчас делает поддержку тяжёлой, а к 5му проекту станет катастрофой.
Canvas + 9 игровых CSSанимаций одновременно.На главной странице одновременно работают requestAnimationFrame canvasлуп, cursormascot, living hero panel с Nature Seed, ambient star particles, constellation, floating runes, background parallax. На среднем Android это 20–30 fps.
Дублирование HTML в карточках игр.Один и тот же HTMLблок <div class="ballcloudfield"> с 16 картинками повторяется дважды — в index.html и presskit.html. Изменение одного требует изменения обоих.
Игровые страницы — фиксированный backdrop + fixed position.На SafariiOS position fixed внутри isolation isolate и overflow hidden работают непредсказуемо. Это один из самых частых багов iOS Safari.
Нет реального fallback для отключённого JS.Если JS не загрузился, сайт показывает пустой canvas, сломанный theme, нерабочие модалки и фильтры. Нет <noscript> ни в одном файле.
Форма контактов — только mailto.Это не форма, это имитация. Для игровой студии 2026 года это сигнал незрелости перед издателями.
3. Что уже хорошо — сохранить и усилить
CSPполитика— одна из лучших в indieигровом секторе. requiretrustedtypesfor script, hashonly inline scripts, connectsrc none. Реально серьёзная работа.
404страница— это конкурентное преимущество. Полноценная canvasигра с кошкой, звёздами, combo, shield, lives — редкость. Оставить и улучшить.
Constellation easter egg— умная идея с hidden glint buttons и секретным паролем из букв игры. Создаёт ощущение живого авторского мира.
Живые карточки игр.Ball is God с летящими камнями, Candy Shop с mergeанимацией, Paint Blasters с chain reaction — это не просто карточки, это минипревью геймплея. Сильно.
gametheme.js — единый модуль темы.Правильное решение один файл управляет темой для всех страниц, хранит предпочтение в localStorage с graceful fallback.
Security check script(securitycheck.mjs) — проверка перед деплоем. Профессионально.
prefersreducedmotion— уважение к пользователям с вестибулярными нарушениями реализовано.
4. Подробный аудит
DESIGN  ART DIRECTION
Сильные стороныСайт имеет узнаваемую визуальную систему — акварельная эстетика Nature Seed, конфетная мягкость Candy Shop, броская индустриальность Paint Blasters, небесная мифология Ball is God. Каждая игра получила свою цветовую тему через CSS custom properties (gameaccent, gamewarm). Это грамотно.
Слабые стороны
Hero section на главной перегружен. Одновременно canvas с котом, living nature panel, floating runes, constellation demo, portal badge, magic hud, heroworlds nav. Взгляд не знает, куда идти. По правилу Hicks Law — чем больше выборов, тем дольше решение.
Типографика используется systemuiInter. Для игровой студии с таким визуальным амбишном это слабо. Нет фирменного акцента в шрифте. Хотя бы один displayшрифт для заголовков дал бы +2 балла к «premium feel».
Кнопки .btnprimary выглядят хорошо (gradient + glow), но при скролле все CTA ведут на mailto — это снижает доверие к studii как к профессиональной организации.
Футер минималистичный — это нормально, но brand name теряется среди ссылок. Footer для игровой студии должен быть финальным «whopper» — минивитрина.
Отсутствует loading screen  intro animation. Когда пользователь первый раз заходит, canvas появляется резко. Нет плавного появления мира WillowinWorld.
UX  USER EXPERIENCE
Информационная архитектураимеет проблему навигация содержит Home  Games  Studio  Devlog  Press Kit  Contact — 6 пунктов, что нормально. Но Studio ведёт к якорю studio на той же странице, а не к отдельной странице. При добавлении команды, истории, карьеры — придётся переделывать всю структуру.
Devlogразделён краткие карточки на главной + полные логи на страницах игр. Это создаёт путаницу. Пользователь кликает «Open Devlog» и оказывается на той же странице, но прокрученной вниз. Непонятно.
Фильтры игрработают по тегам, но теги слишком широкие (Mobile, Physics, Cozy). Пользователь не может фильтровать по статусу — "In Beta", "Coming Soon", "Released".
Нет search.На небольшом сайте это не критично, но devlog при расширении до 20+ записей станет нечитаемым без поиска.
Контакты— форма открывается в модальном окне и отправляет через mailto. Это не работает для пользователей без emailклиента (часть молодой аудитории использует только вебпочту). Нет Telegram, Discord, TwitterX.
Press Kitхорош по структуре, но не хватает downloadable zip с ассетами, логотипами и fact sheet в PDF.
FRONTEND  CODE QUALITY
CSS архитектура — главная проблема кода.9 000 строк в одном файле styles.css без @layer, без разделения по компонентам, без BEM или другой методологии. Есть условная группировка по компонентам, но порядок непредсказуем — .natureherolayout находится в 3 разных местах файла.

Доступность (A11y)
arialabel="Game page navigation" на каждой странице игры — хорошо.
Но в 404.js динамически создаются canvasэлементы без altтекста.
В scripts.js функция drawCat() рисует кота на canvas — нет текстового эквивалента для screen readers.
Некоторые декоративные <span> без ariahidden="true".
scripts.js — 1800 строк в одном файле.Canvas rendering, modal management, game logic, секреты, theme management, фильтры, FAQ, smooth scroll — всё в одном IIFE. Это антипаттерн для maintainability.
Inline <style> в 404.cssначинается с отступом в 4 пробела — это визуально выглядит как embedded styles, но это отдельный файл. Минорно, но нечисто.
gametheme.jsиспользует document.querySelectorAll("[datalogotheme]") — это правильно. Но функция initCursorMascot вызывается 5 раз с повторяющимися объектами конфигурации. Можно вынести в массив и пройти циклом.
PERFORMANCE
Самая острая проблема — requestAnimationFrame на главной странице.scripts.js запускает canvas loop с вызовами
drawCachedBackground() — рисует замок, долины, облака, willow leaves
drawStars() — итерирует по 92 звёздам
drawParticles() — 70 частиц
drawConstellation() 
drawCat() — сложная геометрия или изображение
drawBursts() — при кликах
Это 60 fps canvas loop. На слабых устройствах это убивает батарею и создаёт thermal throttling.
Уже реализованные меры (хорошо)
targetFrameInterval() — ограничение до 31fps для lowmotion
backgroundCacheKey — кэширование статичного фона
IntersectionObserver для паузы анимаций карточек вне вьюпорта
prefersReducedData detection
Чего не хватает
OffscreenCanvas для canvasработы в worker
Throttling pointermove — сейчас каждое движение мыши вызывает startLoop()
willchange transform добавлен на .naturecursormascot, но не на все анимированные элементы
CSS анимации .ballcloud— 16 элементов с animation ballCloudDrift — это дорого
Шрифт Inter загружается через systemui — хорошо, не нужен внешний fetch. Но если добавят Google Fonts — нужен fontdisplay swap
LCP проблема<link rel="preload"> добавлен для ключевых изображений — правильно. Но canvas рисуется поверх всего и может мешать LCP detection.
CLSCanvas position fixed с zindex 1 — не должен вызывать CLS. Но модальные окна при открытии добавляют overflow hidden на body — это может вызвать layout shift на страницах с видимым scrollbar.

MOTION DESIGN
Что работает отлично
Nature Seed цикл (sketch → painted → water drops → tree bloom → companions) — это кинематографично
Candy Shop merge animation — тайминги правильные, satisfying
Ball is God platform gate animation — читается геймплей
Paint Blasters cube blast — chain reaction понятна
Что стоит пересмотреть
.ambientonly класс — правильная идея (паузить при lowmotion), но реализация через CSS animationplaystate означает, что элементы всё равно занимают место и создают paint — они просто заморожены. Лучше display none или visibility hidden с @media (prefersreducedmotion).
Hover эффект на gamecard (hoverafter с radialgradient shine) — хороший touch. Но вычисляется каждый pointermove через JS (card.style.setProperty("shinex")). Это нормально, но только при (hover hover) and (pointer fine) — что уже проверяется.
Constellation play mode — интересный интерактив, но его сложно обнаружить. Нет явной подсказки пользователю, что нужно кликать на звёзды.
BRANDING
СильноЛоготип «два W» (WillowinWorld) концептуально продуман — «двойной мир», «портал», «созвездие». SVG реализация с полилиниями читается хорошо.
Слоган"creates magical mobile games that feel alive" — хороший, но слово «magical» сейчас стало generic в indieсекторе. Сильнее было бы чтото более конкретное "Tactile worlds. Real feel. Four games in the making." или "We build games that feel like they breathe.".
ПозиционированиеСтудия позиционирует себя как «mobilefirst + cozy physics + premium art». Это рабочая ниша, но на сайте это читается только на 4м экране. Первое, что видит издатель — анимированный фон, потом текст. Нужен более агрессивный headline на первом экране.
Tone of Voiceсейчас — поэтичный, немного загадочный ("Draw water paths. Wake the forest.", "Drop through heaven. Survive the fall."). Это правильно для B2C. Но для B2B (издатели) нужен параллельный более деловой tone — например, отдельная publishers страница.
Нет social proof.Ни одного отзыва, ни одного медиаупоминания, ни одного числа (downloads, wishlist, beta signups). Даже один "5,000 beta signups" полностью меняет восприятие студии.
SECURITY
Очень сильная позиция для static site.Разбор
CSP в _headers
scriptsrc self sha256YEmRj4MUCAFjWbGin8kF7Sx3sRy60JEX+N5xb8TIze4=
SHA256хэш для единственного inline скрипта (JSONLD) — правильно. connectsrc none — нет внешних запросов. frameancestors none — защита от clickjacking.
requiretrustedtypesfor script — это Trusted Types API. Браузерная защита от DOM XSS. Для 2026 года это передовая практика.
Что нужно проверитьулучшить
StrictTransportSecurity maxage=31536000 — без includeSubDomains. Если когдалибо появится поддомен без HTTPS, это дыра. Добавить includeSubDomains как только все поддомены будут готовы.
ReferrerPolicy strictoriginwhencrossorigin — правильно.
PermissionsPolicy — исчерпывающий список, хорошо.
Реальные риски
1. Форма контактов через mailto — не является security risk сама по себе, но значит нет serverside ничего. Если добавят реальную форму позже — нужны CSRF токены, rate limiting, honeypot fields.
2. localStorage используется для темы. trycatch обёртка есть. Валидация значения есть (=== "dark" === "light"). Это правильно.
3. JavaScript секреты игр (gameSecretRewards) — логика захардкожена в frontend. Как указано в SECURITY.md, это намеренно — нет реальных наград. Правильное решение для static site.
4. securitycheck.mjs проверяет наличие токенподобных строк через regex \b[AZ09]{3,}([AZ09]+){1,}[AZ09]{2,}\b. Это может дать false positives на IDстроки.
5. Нет .wellknownsecurity.txt в проверяемых файлах — хотя securitycheck.mjs ожидает его (securityTxt). Значит он существует, просто не включён в список файлов.

6. Productionready рекомендации
Перед деплоем обязательно
Тестирование на реальных устройствах.iPhone SE (старый), Samsung Aсерия (midrange Android), iPad Safari. Конкретно проверить position fixed backdrop на iOS 16+, проверить canvas fps на Android Chrome.
Запустить Lighthouse в incognito.Целевые показатели Performance >70 mobile, >90 desktop. LCP <2.5s. CLS <0.1.
CSP тест через reportonly mode.Добавить ContentSecurityPolicyReportOnly с reportto эндпоинтом (можно Sentry или Report URI). Посмотреть, нет ли неожиданных violations.
HSTS preload.Добавить preload к StrictTransportSecurity и сабмитнуть на hstspreload.org после стабилизации сайта.
Оптимизация изображений.Проверить все .webp через Squoosh — убедиться что нет изображений >200KB для thumbnails и >512KB для hero.
Запустить node toolssecuritycheck.mjs— уже реализован, запустить и убедиться что всё проходит.
Добавить sitemap.xml autoupdate.Сейчас lastmod 20260524 — статическое. Это нормально для static site, но напоминание обновлять при каждом деплое.
Robots.txt проверка.Текущий robots.txt разрешает всё кроме private, admin, api — которых нет. Это нормально, но лучше добавить Disallow tools чтобы скрыть security check script от индексации.
7. Идеи для улучшения (20 конкретных)
Интерактив и woweffect
1. Звук при constellation completion.Короткий Web Audio API sound (без external файлов, через AudioCon oscillator) — магический аккорд когда созвездие завершено.
2. Cursor trail с тематическими частицами.Сейчас trail — просто белыеcyan линии. Когда пользователь на странице Nature Seed — курсор оставляет зелёные листья. На Paint Blasters — краска. На Candy Shop — конфетти.
3. Parallax при скролле для hero.Сейчас hero panel — статичный (кроме canvas). Лёгкий translate на scroll event (через IntersectionObserver + CSS variable) на hero panel создаёт глубину.
4. Game card flip on mobile tap.На мобильном нет hover. Тап на карточку — плавный flip 180° — back side показывает краткие stats + кнопку.
5. Typing animation для hero headline."creates magical mobile games that feel alive" появляется по буквам при первой загрузке. Один раз, не зацикленный.
6. Progress bar для Nature Seed beta.Живой (анимированный fill) progress bar с countdown до July 2026. Можно обновлять через static JSON.
7. Seasonal theme.В зависимости от месяца — небольшие изменения palette зима → снег на castle, весна → цветы на willow. Через JS Date.
8. Waitlist counter."4,238 players waiting for Nature Seed beta" — обновляется через static JSON файл при каждом деплое. Создаёт FOMO.
Дизайн и брендинг
9. Display font для заголовков.Одна семья — например, Bricolage Grotesque или Clash Display (оба бесплатные, variable). Только для h1, h2 — не для UI. Загружать через <link rel="preload"> с fontdisplay optional.
10. Animated logo.При hover на логотип в header — два W плавно расходятся и сходятся как крылья или портал. SVG SMIL или CSS animation.
11. Game world minimap.В footer — маленькая SVGкарта «мира WillowinWorld» с 4 территориямииграми, кликабельная.
12. издательpage publishers.Отдельная страница studio stats (team size, founded, focus), games summary, contact form с полем «Inquiry type Publishing  Investment  Partnership». Другой tone of voice — деловой.
Контент и UX
13. Devlog как RSS.Добавить feed.xml — журналисты и фанаты могут подписаться. Это бесплатный marketing канал.
14. Wishlist email capture.Вместо mailto для beta — простая форма с email + game selector. Netlify Forms или Formspree (бесплатный tier). Пользователь видит success state.
15. Video preview для игр.На страницах игр — 15секундный .webm без звука, autoplay, loop, muted — показывает реальный геймплей. Лучше любого статичного скриншота.
16. Keyboard shortcuts.T — toggle theme, G — goto games, P — press kit. Для power users и журналистов. Показать в маленьком tooltip при первом посещении.
Performance
17. Service Worker для offline.При повторном посещении сайт загружается мгновенно из cache. Для игровой студии это демонстрация технической культуры.
18. contentvisibility auto на нижних секциях.Studio, Systems, Process, FAQ — добавить contentvisibility auto с containintrinsicsize. Браузер не рендерит то, что вне вьюпорта.
19. Canvas worker.Перенести background rendering в OffscreenCanvas + Web Worker. Главный thread освобождается для UI interaction. Значительный прирост на mobile.
20. Аналитика без cookies.Plausible.io или Umami (selfhosted) — privacyfirst аналитика. Можно показать «X visitors this month» публично как social proof. CSP нужно обновить для их домена.

class CanvasLoop {
rafId = null;
visible = true;
pointerActive = false;
pointerTimer = null;
reducedMotion = window.matchMedia((prefersreducedmotion reduce)).matches;
start() {
if (this.rafId this.reducedMotion) return;
this.rafId = requestAnimationFrame(t => this.tick(t));
}
pause() {
if (this.rafId) {
cancelAnimationFrame(this.rafId);
this.rafId = null;
}
}
onPointerMove() {
this.pointerActive = true;
this.start();
clearTimeout(this.pointerTimer);
 Пауза через 4 секунды бездействия

this.pointerActive = false;
if (!this.visible) this.pause();
}, 4000);
}
tick(now) {
this.render(now);
 Не планировать следующий frame если всё idle
if (this.visible && this.pointerActive) {
this.rafId = requestAnimationFrame(t => this.tick(t));
} else {
this.rafId = null;
}
}
}

1. Что ещё удалось найти
По дизайну
Шрифт Inter через systemui fallback— на Windows 11 systemui резолвится в Segoe UI Variable, на macOS в SF Pro, на Android в Roboto. Три разных шрифта → три разных метрики → потенциальный CLS и визуальное несоответствие между платформами.
letterspacing 0 на h1h2— для displayтекста размером 5–6rem нулевой letterspacing выглядит плотно. Обычно крупный текст выигрывает от отрицательного трекинга (0.02em to 0.04em).
Цветовой токен cyan имеет разные значения в darklight— 71e7ff vs 08a9c9. Это разные цвета, не просто разная яркость. В некоторых компонентах это создаёт визуальную непоследовательность.
Game card hover transform translateY(8px)— без willchange transform это может вызвать repaint на картах со сложными backdropfilter.
Press Kit страница— hero h1 "Four living game worlds, packaged for press and publishers" — слово «living» здесь теряет смысл (пресскит не живой). Несоответствие тону.
По UX
Constellation easter egg не discoverable.Кнопки .secretglint имеют fontsize 0 и opacity 0 по умолчанию. Анимация secretPulse показывает их с opacity 0.54 только на 32–48% цикла. Пользователь может провести на сайте 10 минут и не заметить ни одной. Это не easter egg — это невидимый контент.
После завершения constellation (state.completed = true) сайт не даёт никакой долгосрочной награды.successBadge показывается 4.2 секунды и исчезает. Нет сохранения в localStorage, нет unlocked content. При перезагрузке — сброс. Пустое ощущение.
Фильтры игриспользуют datatags строку для matching (tags.includes(filter)). tags.includes("Physics") сработает для "Water Physics" — это правильно. Но tags.includes("In Development") сработает только если точная строка "In Development" есть в datatags. На index.html в ballcard datatags содержит "In Development" — окей. Но фильтр "Magic" возвращает только Nature Seed и Candy Shop — Ball is God и Paint Blasters не имеют тега Magic, хотя оба игровых мира содержат магический элемент.
Форма в модальном окне— после submit открывается emailклиент. contactForm.reset() и closeContactModal() вызываются сразу, не ожидая. На мобильном это выглядит так модальное окно закрывается, появляется emailприложение. Если пользователь не имеет настроенного email — они видят системный диалог «нет приложения», и непонятно, отправилось ли сообщение.
Back navigationс game pages — <a href="..index.htmlgames">Games<a>. При клике браузер перезагружает главную страницу и скроллит к games. Анимации canvas запускаются заново, что создаёт мигание. Нет history.back() как альтернативы.
По frontend
securitycheck.mjs проверяетналичие inline scripts через regex <script\b([^>])>gi. Фильтрует скрипты без src и без type=applicationld+json. Но не фильтрует type="module" — если добавить <script type="module">, он пройдёт проверку без hash в CSP, что будет security violation.
gametheme.js загружается без defer или asyncна всех game pages <script src="..gametheme.js"><script> в конце body — это лучше чем в head, но всё равно блокирует rendering финального кадра. defer здесь безопаснее.
404.js использует new Image() для загрузки sprites, затем обрабатывает их через createCanvas + getImageData для удаления белого фона. Это означает что sprites грузятся без crossOrigin атрибута — на Cloudflare Pages это нормально (sameorigin), но если CDN сменит домен — CORS ошибка.
В scripts.js функция getStructuredDataHash()в securitycheck.mjs ищет JSONLD через regex с lookahead. Этот regex работает для текущей структуры, но хрупкий — любое изменение атрибутов <script> тега (порядок id и type) сломает проверку.
initGameAnimationVisibility()добавляет isanimationpaused на все game cards через IntersectionObserver. Но observer использует rootMargin "260px 0px" — это означает карточки начинают анимироваться за 260px до появления во вьюпорте. На медленных устройствах это означает анимации работают дольше чем нужно.
По performance
backdropfilter blur(18px) на .siteheader— один из самых дорогих CSS эффектов. На mobile Chrome это создаёт отдельный compositor layer. Хуже — header position fixed, что означает он перерисовывается при каждом скролле на устройствах без CSS scrolldriven animations поддержки.
В scripts.js функция drawBackground() вызывает drawCachedBackground()которая рисует в backgroundCache canvas только при изменении backgroundCacheKey. Но drawWillowLeaves() вызывается каждый frame напрямую (не кэшируется). Это правильно для анимированных листьев, но drawWillowLeaves использует Math.sin() и ctx.ellipse() в цикле на каждый из 18 листьев — каждый frame.
state.backgroundStars — массив из 92 звёзд(dark theme). Каждая звезда в drawStars() проверяет расстояние до курсора (Math.hypot(dx, dy)) и потенциально двигается. 92 операции Math.hypot + возможные star.x += ... на каждый frame — на lowend устройствах это заметно.
drawGrass() функция существуетв scripts.js но не вызывается в основном render loop! Функция полностью определена (120 блейдов травы с quadraticCurveTo), но закомментирована или пропущена в вызове. Это мёртвый код, увеличивающий bundle size.
CSS repeatinglineargradientиспользуется как ure overlay на ~30 элементах. На GPU это дёшево, но repeatinglineargradient(118deg, rgba(255,255,255,0.052) 0 1px, transparent 1px 14px) на больших блоках (fullscreen sections) создаёт значительную нагрузку при первом paint.
По mobile
initCursorMascot не отключается на touchустройствахполностью — проверка finePointer.matches отсекает touch, но window.addEventListener("pointermove") в gametheme.js слушается всегда. На мобильном pointermove не срабатывает при тапе (только при drag), поэтому практически безопасно, но event listener зарегистрирован впустую.
Hero section на главной при ширине 320px— .heroworlds переключается на gridtemplatecolumns repeat(2, minmax(0, 1fr)). Четыре ссылки → 2×2 сетка. При minheight clamp(66px, 7svh, 78px) на маленьком экране это занимает ~160px — почти экран на SE. Это выдавливает кнопки CTA ниже fold.
.huddots и .huddot— анимированные точки используют boxshadow для glow эффекта. На Android Chrome boxshadow анимация дорогая — каждое изменение вызывает repaint слоя. Сейчас точки не анимируются CSSanimation, но при добавлении animate класса это станет проблемой.
Landscape mode на мобильном— hero sections игровых страниц имеют minheight calc(100svh 74px). В landscape на iPhone это ~350px высоты с большим контентом, который не помещается. Нет специального landscape breakpoint.
По SEO
JavaScriptрендеринг constellation и canvas— весь hero section на главной рендерится Canvas. Google Crawler не выполняет canvas. Headline "WillowinWorld creates magical mobile games that feel alive" присутствует в HTML — это хорошо. Но игровые карточки содержат контент в ariahidden="true" divах — Game cover titles и h3 скрыты за position absolute; zindex 8 что потенциально деиндексируется.
Game pages не имеют BreadcrumbList structured data.Навигация есть в <nav>, но для Google лучше явная BreadcrumbList schema Home > Games > Nature Seed.
Все 4 game pages имеют <link rel="canonical"> с абсолютными URL— правильно. Но presskit.html canonical указывает на httpswillowinworld.compresskit.html а в sitemap.xml эта страница также присутствует — консистентно, хорошо.
sitemap.xml не включает 404.html— правильно, 404 страница не должна индексироваться. Но 404.html имеет <meta name="robots" content="noindex"> — дополнительная защита есть.
Нет hreflang— если студия когдалибо добавит локализованные страницы, без предварительной архитектуры это будет болезненно переделывать.
Internal linking structureслабая. Главная страница ссылается на game pages. Game pages ссылаются назад на главную. Presskit ссылается на главную и game pages. Но нет crosslinking между game pages ("While you wait for Nature Seed, check out Candy Shop"). Это влияет на crawl depth и PageRank distribution.
По accessibility
.faqquestion кнопки используют ariaexpanded— правильно. Но .faqanswer не имеет id и кнопка не имеет ariacontrols. Screen reader знает что чтото раскрылось, но не знает что именно и где это находится.
Canvas в index.html— <canvas class="magiccanvas" ariahidden="true"> — правильно. Но canvas в 404.html — <canvas class="loststarscanvas" id="lostStarsCanvas"> — без ariahidden. Screen reader попытается описать canvas, ничего не найдёт, создаст путаницу.
.gamefilters группа кнопокимеет role="group" и arialabel — хорошо. Но нет arialive на контейнере с результатами. Когда фильтр меняется, screen reader не объявляет что контент изменился.
Heading hierarchy нарушена на game pages.natureseed.html <h1>Draw water paths. Wake the forest.<h1> — это правильно. Затем идут <h2> в секциях. Но <div class="eyebrow">Nature Seed<div> визуально выглядит как heading, но семантически это <div>. Screen reader пропускает его в heading navigation.
Модальные окназакрываются по Escape — правильно. Но при закрытии focus возвращается на activeGameTrigger — только если он сохранён. Если modal открыт программно (не через кнопку), focus может потеряться.
Color contrast muted c2d9e2 на bg 031735 — проверить. c2d9e2 на 031735 даёт примерно 7.11 — проходит AAA. Но muted2 86a4b9 на 031735 — примерно 4.21 — едва проходит AA, не проходит для мелкого текста (<18px).
По security
localStorage.getItem("willowtheme")валидируется (=== "dark" === "light"). Правильно. Но если ктото вручную установит localStorage.setItem("willowtheme", "<script>alert(1)<script>"), валидация вернёт null, и используется системная тема. Никакого XSS риска — правильная защита.
contactForm submit handlerсобирает name, email, type, message через FormData, затем encodeURIComponent для mailto. encodeURIComponent корректно экранирует специальные символы. Но email не валидируется patternом перед отправкой — только type="email" на input, что можно обойти через DevTools.
Нет autocomplete на password полях— не актуально (нет password fields), но стоит добавить autocomplete="name", autocomplete="email" на контактную форму — уже есть! Проверено.
securitycheck.mjs читает файлычерез readFile. Если запустить из неправильной директории, путь new URL("..index.html", import.meta.url) может резолвиться неправильно. Нет проверки что файл существует перед чтением — unhandled rejection возможен.
По защите ассетов
robots.txt не блокирует assetsдиректорию. Google Images индексирует все game art изображения. Это двусторонне бесплатный трафик, но и лёгкое копирование с атрибуцией потери.
Изображения в assets доступны по прямому URL без authentication.Нет hotlink protection в _headers — любой сайт может встроить <img src="httpswillowinworld.comassets..."> и использовать bandwidth без разрешения.

7. Честный вывод
Самые надёжные фиксы (подтверждены источниками)
Отключение backdropfilter на mobile — подтверждено множеством performance postmortems. Chromium team в 20222023 значительно улучшила backdropfilter производительность, но на old Android Chrome (90112) и на Safari iOS < 16 это всё ещё дорого. Источник web.devrenderingbackdropfilter, Chrome Status.
ariacontrols + ariaexpanded для accordion — это WCAG 2.1 APG (Authoring Practices Guide) официальный паттерн. Не мнение — спецификация. Источник w3.orgWAIARIAapgpatternsaccordion.
Canvas ariahidden="true" — стандартная практика. MDN, W3C Canvas A11y spec прямо указывают если canvas декоративный или имеет alternative  representation — ariahidden.
Подходы которые лучше не использовать
OffscreenCanvas в текущей архитектуре — риск высокий, выигрыш сомнителен для сайта без тяжёлых WebGL вычислений. Canvas работает в main thread, но при правильном idlepause большинство frame времени не расходуется. Сложность OffscreenCanvas не оправдывает выигрыш для этого типа визуализации. Источник discussions на web.dev и Chrome Developers blog показывают что OffscreenCanvas выигрывает для computeheavy WebGL, не для 2D canvas с умеренными операциями.
<details><summary> для FAQ вместо текущего JSaccordion — потеряет CSS height animation. Альтернатива без JS и с анимацией gridtemplaterows 0fr  1fr подход уже реализован в текущем коде — это правильно и современно.
Где остаётся неопределённость
iOS Safari position fixed поведение — очень контекстнозависимо. Баг воспроизводится на одних конфигурациях и не воспроизводится на других в зависимости от iOS версии, наличия клавиатуры, и scroll position. Нужно тестирование на реальном устройстве — не симулятор.
defer на gametheme.js — риск FOUC реальный. Тема (lightdark) читается из localStorage. Если скрипт загружается с defer, первый render произойдёт без применённой темы. На медленных соединениях это заметно. Решение добавить blocking inline <style> с минимальной темой + defer для полного скрипта. Но это требует тестирования на slow 3G.

Где нужны дополнительные тесты перед принятием решений
backdropfilter на mobile — реальный профиль FPS нужен с конкретных устройств. Chromium profiler покажет реальную картину.
Canvas idlepause агрессивность — слишком ранняя пауза сделает сайт «мёртвым» при медленном чтении. 4секундный timeout — предположение, нужно user testing или analytics (через pointer event timing).

Критические находки которые не были упомянуты
scripts.js — функция initSecrets() содержит архитектурную уязвимость.
secretRewards массив инициализируется с Math.random() — случайный секрет выбирается при загрузке страницы. Это означает что при каждом refresh пользователь видит разные glint кнопки в разных местах. Пользователь нашёл 3 из 8 букв, обновил страницу — прогресс сброшен, glint кнопки в других местах. Это не easter egg — это Sisyphus experience.
drawCastle() вызывается внутри drawBackground()— а drawBackground() кэшируется в backgroundCache. Это правильно. Но drawCastle() использует ctx.save() и ctx.restore() внутри цикла по 4 башням — это 8 контекстопераций на каждый рекэш. saverestore стекуют state — при глубокой вложенности это медленнее чем думают разработчики. Chrome Source "canvas performance" DevRel team постоянно упоминает saverestore как hidden cost.
processSprite() в 404.js делает floodfill по пикселям(getImageData + manual pixel traversal) для удаления белого фона. Это выполняется для каждого из 10 спрайтов при загрузке страницы. Floodfill на 512×512 изображении — это 262,144 пикселей × несколько операций каждый. На slow mobile это блокирует main thread на 200500ms при загрузке 404 страницы.
manifest.webmanifest объявляет "display" "standalone"и "purpose" "any maskable" для иконки. Maskable icon требует safe zone — 40% padding вокруг содержимого. Если willowinworldlogoday.webp не адаптирован под maskable формат (т.е. логотип занимает всё пространство без отступов), на Android устройствах иконка PWA будет обрезана.
CSS colormix(in srgb, ...) используется повсеместно— это CSS Color Level 5 функция. Поддержка Chrome 111+, Firefox 113+, Safari 16.2+. На Safari 16.016.1 и более старых браузерах все colormix() вызовы fallback к transparent или initial. Это означает что ~35% пользователей видят сайт без акцентных цветов на карточках, бордерах и кнопках. Нет ни одного fallback.
В styles.css используется wrap balanceна section titles и hero . Поддержка Chrome 114+, Firefox 121+, Safari 17.4+. На Safari < 17.4 (значительная часть iOS пользователей на старых iPhone) игнорируется — текст переносится стандартно. Некритично, но стоит знать.
svh  dvh units используются в hero sections(minheight calc(100svh 74px)). svh (small viewport height) — правильный выбор для iOS Safari (учитывает скрытую адресную строку). Поддержка Chrome 108+, Firefox 101+, Safari 15.4+. На старых Safari — fallback на vh нет. Добавить minheight calc(100vh 74px); minheight calc(100svh 74px).
gametheme.js — функция setTheme() меняет logo.srcчерез datalogotheme attribute lookup. Но смена src у img тега вызывает новый HTTP request. Если willowinworldlogoday.webp и willowinworldlogo.webp не кэшированы — каждое переключение темы вызывает network request. CacheControl для assets — public, maxage=31536000, immutable — поэтому второй раз берётся из cache. Но первый toggle всегда создаёт network roundtrip.
initCardShine() добавляет pointermove listener на каждую game card.Четыре карточки × один listener каждый = 4 listeners. При 60fps движении мыши это 60 вызововсекунду, каждый устанавливает два CSS custom properties через style.setProperty. Это дёшево в изоляции, но в сочетании с canvas RAF loop — дополнительная нагрузка. Throttle через requestAnimationFrame внутри pointermove handler был бы правильнее.
fetch_sports_data и другие tools— не релевантно, но в файловом коде замечена странность securitycheck.mjs ожидает файл deploynginxsecurity.conf по пути new URL("..deploynginxsecurity.conf", import.meta.url), но в списке файлов проекта nginxsecurity.conf находится в корне, не в deploy. Это означает security check script падает при запуске с текущей структурой директорий — он проверяет несуществующий путь или другой файл.

5. Практический план
🔴 Сделать в первую очередь
1. Исправить путь в securitycheck.mjs
Это самое критичное — CICD tool сломан. Либо переименовать путь с "..deploynginxsecurity.conf" на "..nginxsecurity.conf", либо создать deploy директорию и переместить конфигурации туда. Проверить node toolssecuritycheck.mjs должен завершаться с "WillowinWorld security check passed.".
2. colormix() fallback
Добавить @supports wrapper или переопределить проблемные переменные с static fallback. Конкретные переменные для исправления accentborder, accentsoft, accentglow. Проверить в Safari 15 и Chrome 110.
3. Предобработанные sprites для 404.js
Переэкспортировать все 10 спрайтов кошки с прозрачным фоном (PNG24 или WebP с alpha). Убрать весь processSprite() код из 404.js — это ~80 строк. Проверить 404 страница загружается без Long Task в профилере.
4. role="status" на toast и gameToast
Два HTML атрибута, 2 минуты работы, немедленный A11y fix.
5. Math.random() → детерминированный seed в initSecrets()
Использовать день месяца как seed const seed = new Date().getDate(). Написать простую seeded random функцию (mulberry32 — 5 строк) которая даёт одинаковые результаты для одного seed. Пользователь видит одни glint кнопки весь день.

7. svh fallback добавить
Перед каждой строкой с svh добавить дублирующую с vh. Две строки на каждый случай. Проверить на Safari 14 (симулятор Xcode).
8. initCardShine() RAF throttle
Обернуть card.style.setProperty вызовы в requestAnimationFrame. Один rAF callback на все cards одновременно — не по одному на card. Профилировать допосле.
9. handlePointerMove throttle
Текущий код записывает trail точку каждые 34ms (pointer.lastMove pointer.lastTrail > 34). Это нормально. Но state.pointer.x = point.x; state.pointer.y = point.y; startLoop() вызывается на каждый pointermove event. startLoop() проверяет if (state.rafId) return — это защита. Но лишняя проверка на каждый event. Добавить throttle через passive listener wrapper.

7. Честный вывод
Самые надёжные фиксы по уровню confidence
Подтверждены спецификациями и не требуют дополнительного тестирования
colormix() browser support — Can I Use показывает точные версии. Safari 16.2+ — это факт. На Safari 15 и ниже colormix() возвращает initial value (прозрачный или unset). Это не мнение, это спецификация CSS Color Level 5 и recorded browser behavior.
role="status" для live regions — это ARIA 1.1 spec. Implicit arialive="polite" для status role. MDN, W3C docs однозначны. Нет вариативности.
processSprite() runtime cost — это измеримо. Canvas getImageData + manual pixel traversal — классическая причина Long Tasks. Подтверждено Chrome DevRel постами о canvas performance и многочисленными Stack Overflow обсуждениями.
securitycheck.mjs path issue — это конкретный код который можно проверить локально за 30 секунд.
Требуют проверки на реальных данных
backdropfilter impact на конкретных устройствах — Samsung Galaxy Aсерия Chrome 20232024 имеет значительно лучшую поддержку чем 20212022. Реальный impact нужно измерить с профилером, не предполагать.
INP values — зависят от реальных user interactions и device performance. Нельзя предсказать без field data. Google Search Console после релиза покажет реальные числа через 28 дней.
pointermove throttle necessity — зависит от реальной нагрузки. На среднем desktop с 60fps мониторм — не проблема. На 120fps мониторе — pointermove fires 2x чаще. Профилировать сначала.
Что нельзя назвать productionready прямо сейчас
Сайт не productionready по трём объективным причинам
Первое — securitycheck.mjs с неправильным путём означает что predeploy проверка не работает. Это инструмент контроля качества, и он сломан.
Второе — colormix() без fallback означает что ~5% реальных пользователей на старых браузерах видят визуально сломанные UI элементы — исчезающие borders, неправильные цвета кнопок, прозрачные card backgrounds.
Третье — processSprite() блокирует main thread на 200500ms при загрузке 404 страницы. 404 страница — это уже error state. Добавлять к ошибке ещё и freeze UI — двойной fail.
Всё остальное из этого аудита — улучшения и polish, не blockers.

Что станет проблемой при росте проекта
Если студия выпустит игру №5, №6, №7 — текущий CSS монолит станет неуправляемым. Каждая игра добавляет ~600800 строк тематических стилей в один файл. К игре №8 это будет 15,000+ строк без архитектуры.
Если появится CMS или реальный backend — current static site architecture потребует полного переосмысления. Devlog как статические HTML страницы не масштабируется для еженедельных обновлений.
Если придут реальные издатели — press kit в текущем виде (без downloadable zip, без PDF fact sheet, без видео) будет недостаточным. Большинство gaming publishers имеют checklist того что должен содержать press kit.
Если сайт получит значительный трафик — отсутствие Service Worker означает каждый посетитель делает полный roundtrip для всех ресурсов. С Service Worker — повторные посетители получают instant load.
